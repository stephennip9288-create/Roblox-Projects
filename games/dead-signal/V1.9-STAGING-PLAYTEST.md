# Dead Signal v1.9 — Private staging acceptance and promotion

## Prepared release path

1. Review the v1.9 feature PR and its exact head SHA. Require green Work Source CI, Lossless Source Patch, Private Staging Preflight, Production Candidate Readiness, and repository validation. Download the four-place lossless staging artifact and its hash/fidelity reports.
2. The controlled private staging workflow is main-only. After source checks pass, merge that exact reviewed source revision. Do not change the v1.8 rollout marker, workflows, manifests, backups or place IDs to trigger a release.
3. **Obtain the owner's explicit v1.9 staging publication authorization before dispatching any publishing workflow.** Then use existing `Dead Signal Controlled Private Staging`, branch `main`, operation `deploy`, confirmation `DEPLOY-PRIVATE-STAGING`. It rebuilds/preflights the exact source and records existing rollback files before uploads. Maps publish before Dispatch. Check every upload result and retain the run/artifacts.
4. Perform the tests below on the actual private Roblox experience. Keep the PR/source SHA, workflow run, returned place versions, device, crew count, map, mode, round and result with each observation. A green cloud build cannot establish native physics, navigation, audio permission or frame times.
5. Fix failures on the same release branch with source changes/tests, rebuild, and repeat staging authorization/deployment as appropriate. Keep public v1.8 running until staging is accepted.

The existing checked-in rollback binaries are historical snapshots, not an automatic backup of the latest live v1.8 revision. The owner required preserving them, so they remain unchanged. Before deployment, review the rollback manifest against the verified v1.8 release artifacts and retain that current known-good release run as well; do not assume an older backup restores today's live build.

## Reproducible Studio setup

Open the four generated `.rbxl` candidates in Studio. They contain staging-only PlaceConfigs. Use Dispatch for live teleport acceptance; an unpublished local Studio session cannot prove cross-place travel.

For targeted testing in an unpublished Studio Play session, switch Command Bar to the server and temporarily select an event for each upcoming ordinary wave:

```lua
local c = require(game:GetService("ReplicatedStorage").DeadSignal.Config)
local event = c.Evolution.events[1] -- 1 Hunt, 2 Redline, 3 Iron March, 4 Breach, 5 Critical Mass
c.Evolution.firstRound = 1
c.Evolution.interval = 1
c.Evolution.events = {event}
c.Evolution.stalkerStart = 1 -- allows the Breach's seventh spawn to be a Stalker
```

Apply this before a new wave starts. Keep the seven-second preparation and advertised attack/blast timings unchanged when checking fairness. Stop Play to discard these in-memory edits and restart before choosing another event. The internal runtime context remains private; no production debug remote is added. Use normal progression and the untouched Config for final whole-run acceptance. Do not publish acceleration settings or edit profile namespaces.

Natural event milestones with current tuning: round 5 Hunt, 10 Redline, 15 Iron March, 25 Critical Mass, 35 Redline, 45 Containment Breach. Boss rounds 20/30/40 take precedence. To inspect every event quickly, change only the event order in a disposable local test copy, then discard that copy. Rare-combination testing can increase `combinedChance` locally and restore it afterward.

## Performance, presentation and evidence

Run solo, two-player and four-player sessions on all maps and both modes. Record minimum/typical client FPS, frame-time spikes, client memory, active NPCs/hazards, server frame time and path failures during the busiest special wave. Compare normal and Low Effects; verify blast/charge warnings remain visible with effects reduced. Profile the cap of 40 NPCs, larger Alpha body radius at doors, eight hazards, and corpse cleanup. Set the performance acceptance threshold from the actual target device and v1.8 baseline; do not substitute an offline renderer for measurements.

Review silhouettes, gait/death direction, plate cracks/seams, smoke readability, lighting restoration after event/exfil/results, and sounds with the intended speaker/headphone mix. Stock cue treatments are implemented; bespoke canine/radio audio remains an optional asset-polish follow-up before final acceptance if the owner finds the current mix insufficient.

**Physical mobile control comparison remains postponed.** This release preserves the existing customizable mobile input code and saved settings. Mobile VFX/readability/performance acceptance is still needed when device testing resumes; no two-thumb usability or device-performance result is claimed here.

Capture server/client output and short gameplay clips for failures. Do not mark live acceptance until the owner has reviewed the result.

## Production promotion plan

Only after owner staging acceptance and separate explicit public release authorization:

1. Freeze the accepted source SHA and ensure production-readiness checks compare identical non-PlaceConfig scripts across all four staging/production candidates.
2. Use the existing **Dead Signal Production Release (Manual Only)** workflow on `main`. Read its current confirmation schema at release time; it presently uses the legacy literal `PUBLISH-V18-PRODUCTION` even though runtime version is 1.9. Do not rename/replace this infrastructure for the feature release. Verify that the rebuilt candidate Config says 1.9.0 and that all destinations are generated production IDs.
3. Review the existing production rollback protection and known-good v1.8 release artifacts before approving the environment/publishing step. Preserve checked-in backup binaries. Never substitute staging IDs or keys.
4. Record returned production place versions; perform short public smoke tests for loading/travel/profile continuity and gameplay. On failure, follow the existing controlled rollback procedure using the reviewed known-good release artifacts and manifest. Report any rollback mismatch explicitly.

Nothing in this document is authorization to publish staging or production.
